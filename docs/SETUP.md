# Настройка

1. Установите зависимости и соберите сервис по командам в корневом README.
2. Создайте закрытый `/etc/homenode.env` по `services/home-api/deploy/homenode.env.example`; задайте обязательные пароли и токен бота вне Git.
3. Убедитесь, что пользователь службы может записывать в `HOMENODE_MUSIC_DIR`. Установите `ffprobe`, если нужна сортировка по тегам файлов.
4. Разверните бинарный файл и обновлённый `homenode.init`, затем перезапустите службу.
5. Привяжите бота через экран Telegram в HomeNode. Пришлите ему MP3/M4A или другой поддерживаемый музыкальный файл до 20 МБ. Откройте `/music` и проверьте обе кнопки. На сайте откройте отдельную вкладку «Музыка».

Вкладка «Манга» сканирует медиатеку на EPUB-книги с растровыми страницами. Страница чтения и настройки хранятся в базе HomeNode; обычное обновление бинарного файла не сбрасывает историю.

При ошибке загрузки проверьте доступ Bot API через VPN, свободное место и права на каталог. Большие файлы добавляйте через SMB.

## Устройства и VPN

Панель «Устройства» показывает DHCP-клиентов и соседей из ARP на `br-lan`. Клиент со статическим IP появится после обмена трафиком с роутером; без DHCP-аренды и ARP-записи спящее устройство пассивно обнаружить нельзя. Для режима «Весь VPN» выбирается MAC-адрес устройства: IPv4-пакеты маркируются на входе в LAN и направляются в таблицу VPN с blackhole-резервом, IPv6 блокируется, чтобы не уйти в обход туннеля. Проверьте, что у клиента шлюзом указан именно HomeNode.

## Разовый импорт музыки с Windows без Telegram API

Если музыка уже находится на Windows, можно не пересылать её в Telegram. Запустите на Mac `scripts/import-windows-music.py`, указав Windows SSH-хост, ключ, SFTP-путь к музыке и смонтированный каталог `/media/music` ресурса HomeNode. Для скрипта нужны Python-пакеты `paramiko` и `mutagen` в отдельном виртуальном окружении. Сначала используйте `--limit 1` для проверки, затем запустите без ограничения.

Скрипт читает Windows-каталог без изменений, копирует только MP3/FLAC/M4A/AAC/OGG/Opus/WAV, проверяет размер и SHA-256 после записи на SSD, пропускает точные дубли уже имеющихся файлов и размещает новые треки как `Исполнитель/Альбом/Трек`. Нужны свободное место и стабильное подключение SMB; папка источника и SSH-ключ не записываются в Git. Дубли определяются по точному содержимому файла, поэтому разные кодировки или версии одной песни считаются разными файлами.

## Временный импорт файлов больше 20 МБ через Mac

1. Получите собственные `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` на `my.telegram.org` → API development tools. Запишите их только в закрытый локальный `.env` по образцу `scripts/telegram-local-api.env.example`; не отправляйте в Git.
2. Соберите официальный `tdlib/telegram-bot-api` для Mac с `--local`. На Mac должен быть смонтирован SMB-ресурс SSD роутера. Под каталог файлов сервера выделите отдельную папку внутри этого ресурса. Локальную рабочую папку сервера оставьте на Mac.
3. Запускайте сервер через `scripts/run-telegram-local-api-macos.sh PRIVATE_ENV BINARY WORK_DIR SSD_FILES_DIR`. Скрипт откажется стартовать, если каталог файлов не находится на SMB. API слушает только `127.0.0.1:8081` Mac.
4. Создайте закрытый reverse tunnel скриптом `scripts/run-telegram-api-tunnel.sh SSH_KEY KNOWN_HOSTS root@ROUTER_IP`. Он делает Mac API доступным только как `127.0.0.1:8081` на роутере.
5. Лишь после проверки сервера и туннеля выполните `logOut` бота с публичного Bot API и переключите `TELEGRAM_API_BASE_URL` HomeNode на `http://127.0.0.1:8081`. Установите `TELEGRAM_MAC_FILES_PREFIX` (путь Mac к SMB-каталогу файлов) и `TELEGRAM_ROUTER_FILES_PREFIX` (тот же каталог на роутере). Обновите бинарник и OpenWrt init-скрипт.
6. Пришлите один большой файл, проверьте его появление в медиатеке и обе кнопки. Только после этого отправляйте всю коллекцию. Пока импорт идёт, Mac должен оставаться включённым и SMB-ресурс — подключённым.

Файлы кеша локального Bot API остаются на SSD отдельно от медиатеки. Не удаляйте их до завершения импорта и проверки всех треков. Переход обратно на публичный Bot API планируйте отдельно: одновременный polling через два сервера может потерять обновления.
