# Журнал работ

## 2026-10-06 — Исправлен второй полноэкранный режим видео

Что сделано: проверены обе кнопки полноэкранного режима. Кнопка HomeNode разворачивает весь `player-stage` с подсветкой, но значок в штатных элементах `<video>` разворачивал только видеокадр и показывал чёрные поля. На компьютере при поддержке Fullscreen API штатный значок скрывается через `controlslist="nofullscreen"` и CSS; верхняя кнопка остаётся. На iPhone и в браузерах без нужного API штатный значок не скрывается.

Изменённые файлы: `services/home-api/internal/webui/static/app.js`, `styles.css`, `index.html`, `sw.js`, `docs/PROJECT_STATE.md`, `docs/AI_WORKLOG.md`.

Как проверить: открыть видео на компьютере, убедиться, что в штатной полосе видео нет отдельного значка полного экрана; нажать «На весь экран» над видео и убедиться, что подсветка заполняет область вокруг кадра. На iPhone штатное управление должно сохраниться. Проверка на конкретном ПК владельца ещё нужна.

Риски: некоторые браузеры могут игнорировать `controlslist`; в таком случае верхняя кнопка всё равно работает, но штатный значок может остаться видимым.

## 2026-10-06 — Видеоплеер с подсветкой вокруг кадра

Что сделано: обновлена компоновка окна плеера; список серий на компьютере расположен сбоку, на телефоне — под видео. Добавлены выключатель динамической подсветки, полноэкранный режим с подсветкой, заполнение свободной области со всех четырёх сторон кадра и обнаружение симметричных чёрных полос, уже записанных в видео. После отзыва владельца интервал обновления на ПК сокращён с 350 до 100 мс, на телефоне установлен 180 мс. Изучен [projector-2d](https://github.com/WesselKroos/youtube-ambilight/blob/develop/src/scripts/libs/projector-2d.js) в youtube-ambilight: он проецирует уменьшенный кадр с обрезкой полос и масштабирует несколько слоёв. Для HomeNode выбран более простой вариант: отдельные полосы по четырём краям активного кадра растягиваются к своим сторонам; код проекта не копировался, новая зависимость не добавлялась. Само видео и потоковый backend не изменялись.

Изменённые файлы: `services/home-api/internal/webui/static/index.html`, `app.js`, `styles.css`, `sw.js`, `docs/PROJECT_STATE.md`, `docs/PLAN.md`, `docs/AI_WORKLOG.md`.

Почему: прежняя подсветка была лишь свечением вокруг окна и не заменяла чёрные поля на мониторе; к тому же цвет менялся с заметной задержкой.

Как проверить: открыть любое видео в HomeNode, включить «Подсветка», нажать «На весь экран» и посмотреть сцены с разным соотношением сторон и цветом. Чёрные поля сверху, снизу и по бокам должны показывать размытый цвет кадра. Выключатель возвращает обычный тёмный фон. На паузе цвет фиксируется. Проверки `node --check`, `git diff --check` и `go test ./services/home-api/...` прошли; локальный браузер показал воспроизведение и полноэкранный режим. Обновлённый сервис развёрнут на роутере, перед заменой бинарника оставлены резервные копии.

Риски и ограничения: iPhone/Safari, Tailscale, батарея телефона и точное поведение на всех форматах ещё не проверены. Эвристика встроенных полос может ошибаться на особенно тёмных сценах. Для ambient-полноэкранного режима нужно использовать кнопку HomeNode «На весь экран», а не значок полноэкранного режима внутри стандартных элементов видео.

## 2026-10-02 — Устройства со статическим IP и полный VPN

Что сделано: список устройств дополнен записями ARP только с локального моста `br-lan`; DHCP-клиенты не дублируются, записи WAN и неполные ARP не показываются. Полный VPN дополнен маркировкой IPv4 по MAC, чтобы работать и без DHCP-аренды. Старые правила по IP оставлены совместимыми.

Изменённые части: `services/home-api/internal/server/devices.go`, `devices_test.go`, `scripts/homenode-vpn-policy`, `docs/PROJECT_STATE.md`, `PROJECT_MAP.md`, `DECISIONS.md`, `SETUP.md`, `AI_WORKLOG.md`.

Проверка: тест API с клиентом без DHCP-аренды, дубликатом DHCP/ARP, неполной ARP и WAN-записью; `go test ./services/home-api/...`, `go vet ./services/home-api/...`, `sh -n scripts/homenode-vpn-policy` и `nft -c`. На роутере `/health` вернул HTTP 200; сайт показал 8 устройств вместо 6 (два со статическим IP), выбранный телевизор — в режиме «Весь VPN». MAC телевизора появился в наборе `full_clients`, маршрут пакета с VPN-меткой ведёт через `awg0` и таблицу `51820`. Рабочий бинарник и скрипт политики сохранены как резервные копии перед обновлением.

Риски: пассивный список не обнаруживает спящие устройства, которые не имеют ни аренды, ни ARP. Перезапуск HomeNode затрагивает веб-интерфейс на несколько секунд; роутер не перезагружался. На момент проверки телевизор не отвечал на ping и не создавал нового внешнего трафика, поэтому реальный выход именно с него через VPN ещё не подтверждён счётчиком пакетов; конфигурация маршрута проверена.

Проверка: дымовой импорт одного файла, затем полный импорт без ошибок; для одного FLAC отдельно сравнены SHA-256 на Windows и роутере (совпали). На роутере подсчитаны 1258 настоящих аудиофайлов, ноль `.part`, работающая служба HomeNode и 149,3 ГБ свободного места. Скрипт проверен `py_compile`.

Риски: совпадением считается идентичный файл целиком; разные кодировки/версии одной песни не удаляются. Для повторного запуска нужен доступ Mac к Windows SSH и смонтированному SMB-ресурсу HomeNode. Приватный SSH-ключ и музыка в Git не добавляются.
