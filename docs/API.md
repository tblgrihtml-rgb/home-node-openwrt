# API: изменение для музыки

## GET /api/anime/{releaseID}

Возвращает данные AniLiberty по релизу, включая список эпизодов. Требуется сессия HomeNode; используется Telegram-ботом для сверки новых серий.

## GET /api/library

Для аниме-тайтлов ответ дополнительно содержит `release_id`, если релиз AniLiberty сопоставлен с папкой медиатеки. Бот использует этот ID для уведомлений о новых сериях.

## GET /api/media/stream?path=...&download=1

Возвращает исходный медиафайл как вложение (`Content-Disposition: attachment`) вместо встроенного воспроизведения. `path` — путь внутри настроенного медиакаталога. `download=1` необязателен; без него сохраняется прежнее потоковое поведение и HTTP Range.

Авторизация: обязательна сессия HomeNode. Ответ: 200/206 и байты файла. Ошибки: 400 при неверном пути, 404 если файл отсутствует, 401 без входа.

Импорт в Telegram обрабатывается Bot API long polling, отдельного публичного HTTP endpoint нет.

## Манга

### GET /api/manga

Возвращает EPUB-книги с изображениями в медиатеке, числом страниц, ссылкой на обложку и сохранённой страницей.

Авторизация: обязательна сессия HomeNode.

### GET /api/manga/page?path=...&page=...

Возвращает одну растровую страницу EPUB. `page` отсчитывается с нуля. Путь ограничен `.epub` внутри медиатеки; архивные записи больше 32 МиБ не выдаются.

Авторизация: обязательна сессия HomeNode.

### PUT /api/manga/progress

Сохраняет последнюю страницу. Body: `{"path":"...epub","page":0,"page_count":123}`. Требуется сессия и заголовок `X-HomeNode-Request: 1`.

## Музыкальный каталог и очередь

Все маршруты требуют сессии HomeNode. Изменяющие запросы требуют `X-HomeNode-Request: 1`.

### GET /api/music/search?q=...

Ищет до 20 треков по названию/исполнителю в каталоге iTunes. Ответ: `{"tracks":[{"id":617154366,"title":"...","artist":"...","album":"..."}]}`. Ошибка 502 означает недоступность каталога.

### GET /api/music/status

Показывает `verified`, `expires_at`, `cooldown_until` и название внешнего источника. Секрет сессии не выдаётся.

### POST /api/music/verify/start

Создаёт одноразовую ссылку для браузерного подтверждения источника. Ответ: `{"url":"https://..."}`. Внешний сервис принимает только loopback callback `127.0.0.1`, поэтому браузер после проверки покажет недоступный локальный адрес с одноразовым `grant` в строке адреса.

### POST /api/music/verify/complete

Body: `{"callback_url":"http://127.0.0.1:53672/session-grant?state=...&grant=..."}`. Одноразово завершает проверку; требует входа в HomeNode и короткоживущих `state` и `grant`. Ответ: `{"verified":true}`; 400 — неправильный или устаревший адрес. Значения не должны попадать в журналы и не следует передавать их другим людям.

### GET /api/music/jobs

Список до 200 записей очереди с состояниями `queued`, `running`, `retry`, `verification`, `done`, `failed`.

### POST /api/music/jobs

Body: `{"track_id":617154366}`. ID перепроверяется на сервере по каталогу; URL файла от браузера не принимается. Ответ 202 содержит запись очереди. Ошибка 409 — очередь заполнена.

### POST /api/music/jobs/{id}/retry

Повторяет неудачную или ожидающую проверку запись. Ответ: `{"ok":true}`; 409 — запись нельзя повторить.

### DELETE /api/music/jobs/{id}

Удаляет только запись из очереди, не музыкальный файл. Активную загрузку удалить нельзя. Ответ: `{"ok":true}`; 409 — загрузка ещё выполняется.
