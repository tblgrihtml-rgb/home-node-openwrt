# Решения

## Очередь отдельных музыкальных треков на роутере

Дата: 2026-10-17.

Причина: владелец хочет искать отдельные треки и скачивать FLAC даже когда внешний источник уходит на временную паузу.

Варианты: запуск настольного SpotiFLAC на постоянно включённом Mac; самостоятельный тяжёлый Python/Docker-сервис; очередь в существующем Go API HomeNode.

Выбран существующий Go API и SQLite: один фоновый загрузчик, статусы/повторы в базе, запись только на смонтированный SSD. Метаданные ищутся через iTunes, соответствие записи Tidal определяется через Songlink, поток запрашивается у SpotiFLAC Community после ручной браузерной проверки. Использован протокол клиента из MIT-кода SpotiFLAC v7.2.2 с указанием происхождения в `internal/music/session.go`.

Минусы: сторонний сервис может изменить проверку, ограничить запросы или прекратить работу; Apple/Songlink могут не найти нужную запись; по одному лишь названию нельзя на 100% гарантировать тот же мастер аудио. Сервис принимает только loopback callback, поэтому после браузерной проверки нужно вручную перенести одноразовый адрес в HomeNode; полный end-to-end результат проверяется отдельно. Музыкальные теги и обложки внутри FLAC не записываются.

Что может потребоваться дальше: заменить источник на официальный с собственной учётной записью, добавить сверку длительности/ISRC и метаданные FLAC, если владелец будет пользоваться функцией регулярно.

## Полный VPN для устройств со статическим IP

Дата: 2026-10-02.

Причина: телевизор с постоянным IP виден в ARP роутера, но не имеет DHCP-аренды; старое правило `ip rule` искало адрес только в арендах и не направляло его IPv4 через VPN.

Варианты: получать IP из ARP как запасной источник для `ip rule`; помечать пакеты по MAC-адресу на входе в LAN.

Выбрана маркировка по MAC в `nftables`: она работает и со статическими адресами, и при смене IP, используя существующую таблицу VPN `51820` и её blackhole-маршрут. Прежние IP-правила для DHCP-клиентов оставлены для совместимости.

Минусы: правило действует только на трафик, проходящий через этот роутер; клиент с другим шлюзом или изменённым MAC не подпадает под выбор. Для полноты списка устройств нужны DHCP-аренда либо запись ARP на LAN.

## Временный импорт музыки через существующий бот

Дата: 2026-09-30.

Причина: нужно принять присланные владельцем аудиофайлы без отдельного приложения.

Варианты: загрузка через веб-форму; отдельный Telegram-клиент; существующий Bot API.

Выбран Bot API: он уже работает в HomeNode и проверяет владельца. Метаданные импортов хранятся в новой таблице SQLite, сами файлы — на SSD. Минус публичного режима: ограничение скачивания 20 МБ; для больших файлов см. следующее решение. Удаление временной функции не должно удалять музыку пользователя.

## Локальный Bot API на Mac для крупных файлов

Дата: 2026-09-30.

Причина: музыка владельца больше 20 МБ, а бота и медиатеку нужно оставить на роутере.

Варианты: размещать все процессы на Mac; переносить через SMB вручную; локальный Bot API на Mac с файлами на SSD.

Выбран последний вариант: база и веб-сайт остаются на роутере, Mac временно загружает файлы Telegram в SMB-каталог того же SSD, а запросы бота идут через закрытый SSH-туннель. Минусы: Mac должен быть включён, требуются Telegram API ID/hash, при обрыве SMB импорт остановится. Перед переключением обязательна проверка одного крупного файла.
